# Cloudflare R2 Storage Setup Guide for SnapRoom

SnapRoom uses Cloudflare R2 for zero-egress object storage. Photos are uploaded directly from the client's browser to Cloudflare R2 using AWS S3-compatible presigned `PUT` URLs generated by Spring Boot.

---

## 1. Locate Cloudflare Account ID & S3 API Endpoint

1. Log in to the [Cloudflare Dashboard](https://dash.cloudflare.com/).
2. In the left navigation sidebar, select **R2 Storage**.
3. Under **Account Details** on the right side of the page, find your **Account ID** (a 32-character hexadecimal string, e.g. `262af2d41e3ec867962c3fe20b9481c9`).
4. Copy the **S3 API** URL, which has the format:
   ```text
   https://<ACCOUNT_ID>.r2.cloudflarestorage.com
   ```
5. Set this in `.env`:
   ```env
   STORAGE_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
   ```

---

## 2. Create the R2 Bucket

1. In the **R2** dashboard, click **Create bucket**.
2. Enter the bucket name: `snaproom` (or your preferred name, matching `R2_BUCKET_NAME` in `.env`).
3. Set the location to **Automatic** (or your preferred region).
4. Click **Create Bucket**.

---

## 3. Generate S3-Compatible API Credentials

1. On the main **R2** overview page, click **Manage R2 API Tokens** (in the right panel or top right).
2. Click **Create API token**.
3. Set token permissions:
   - **Token name**: `snaproom-backend-token`
   - **Permissions**: Select **Object Read & Write** (or **Admin Read & Write**).
   - **Specify bucket(s)**: Select **Apply to specific buckets only** -> `snaproom` (or apply to all buckets).
   - **TTL**: Leave blank or set according to your security requirements.
4. Click **Create API Token**.
5. **Important:** Cloudflare only displays these secrets once. Copy:
   - **Access Key ID** (32 hex characters) -> set as `R2_ACCESS_KEY_ID`
   - **Secret Access Key** (64 hex characters) -> set as `R2_SECRET_ACCESS_KEY`

---

## 4. Configure CORS Policy on the Bucket (Critical!)

Because users' web browsers upload photos directly to Cloudflare R2 via presigned `PUT` requests from `http://localhost:3000`, **CORS must be enabled on the bucket** or uploads will be blocked by browser CORS security policies.

1. In the R2 dashboard, click on your bucket (`snaproom`).
2. Go to the **Settings** tab.
3. Scroll down to **CORS Policy** and click **Add CORS Policy** (or **Edit CORS Policy**).
4. Paste the contents of `infra/storage/cors-policy.json`:
   ```json
   [
     {
       "AllowedOrigins": [
         "http://localhost:3000",
         "http://127.0.0.1:3000",
         "https://*.vercel.app"
       ],
       "AllowedMethods": [
         "GET",
         "PUT",
         "POST",
         "HEAD",
         "DELETE"
       ],
       "AllowedHeaders": [
         "*"
       ],
       "ExposeHeaders": [
         "ETag",
         "Content-Length",
         "Content-Type"
       ],
       "MaxAgeSeconds": 3600
     }
   ]
   ```
5. Click **Save**.

---

## 5. Verify Configuration

You can run the backend integration test to verify R2 connectivity:
```bash
cd backend/SnapRoom/SnapRoom
./mvnw test -Dtest=SnapRoomApplicationTests#testR2StorageIntegration
```
Or check the backend health endpoint once running:
```bash
curl http://localhost:8080/api/health
```
The response includes a `storage` health check confirming presigned URL generation and endpoint reachability.
